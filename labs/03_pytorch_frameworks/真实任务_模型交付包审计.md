# 真实任务：可审计的模型交付包

## 背景

训练团队把一个 PyTorch 模型交给端侧部署团队。仅发送一个 `.pth` 文件无法说明模型结构、输入契约、导出版本或 Runtime 结果。本任务要求你交付一个第三方可以重新执行和审计的最小模型包。

## 必须交付

在 `artifacts/` 中生成：

- `challenge_model.pth`：只包含 `delivery_model.py` 中固定 `8 → 16 → 3` MLP 的 `state_dict`；
- `challenge_model.onnx`：输入名 `input`、输出名 `output`，Dynamic Batch；
- `delivery_manifest.json`：输入 Shape/Dtype、Opset、Runtime、固定输入、PyTorch 输出、ORT 输出、误差和工程结论。

## 验收标准

1. Checkpoint 可用 `weights_only=True` 在 CPU 严格加载到固定模型结构，权重均为有限数；
2. ONNX 通过 Checker，单输入 `input`、单输出 `output` 均为 float32，输入与输出 Batch 维均为动态且使用同一个符号，特征维分别为 8 和 3，默认域 Opset 为 17；
3. 固定输入必须为 `torch.linspace(-1, 1, 32).reshape(4, 8)`，输出 Shape 为 `[4, 3]`；Manifest 的名称、Shape、Dtype、Opset 和 Runtime 必须符合约定；
4. 验收器重新加载 Checkpoint，分别执行 PyTorch 和 ORT；两边输出均须有限且最大绝对误差 ≤ `1e-5`；
5. Manifest 中的两份输出必须与实际输出 Shape 相同、绝对误差 ≤ `1e-6`，申报的 `max_abs_error` 与重算值差异 ≤ `1e-6`；不允许通过 NumPy 广播掩盖错误 Shape；
6. 使用额外的固定随机输入实际运行 Batch=1 和 Batch=7，两种情况下输出 Shape 正确、跨 Runtime 最大绝对误差均 ≤ `1e-5`；
7. 至少 100 个字符的中文结论说明输入契约、版本兼容、CPU Fallback、数值容差与目标设备 Benchmark 风险。机器检查长度，内容质量由人工检查。

权重、ONNX 和 Manifest 必须一起提交，工件路径填写同目录文件名。数值基线由验收器从 Checkpoint 计算，不能用 Manifest 中自报的 PyTorch 输出替代。额外 Batch 测试是有限样本验证，不代表对任意输入的等价性证明。

运行 `python challenge_starter.py` 完成 TODO，随后运行 `python validate.py --challenge artifacts/delivery_manifest.json`。
